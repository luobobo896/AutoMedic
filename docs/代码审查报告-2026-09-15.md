## 结论（先看这个）

上一轮（09-08 / 09-09）的多数加固真实成立：跨租户 HTTP/WS 读、跨租户 Confirm 全部 404，WS 归属校验、任务原子抢占、进程组回收、SSH `known_hosts`、`http.Server` 超时、前端 token/401/路由环/世代号均复核为已修。本轮四路各自用实测复现了 **7 个新 P0**，集中在三条主线：

1. **执行结果可以假成功，并连带永久抑制告警**（执行路 P0-A）：dsh 非零退出 / 超时被判 `success`、推空分支、事件闭环标「已修复」，随后同指纹真实告警被 `FingerprintBlock` 永久过滤——平台从此不再处理该故障。
2. **共享工作区在「确认等待期」没有被独占**（执行路 P0-B）：半自动任务 A 待确认期间任务 B 跑完，A 的确认会把 B 的未提交改动提交进 A 的分支、A 自己的补丁丢失，任务仍标 `success`。
3. **授权与部署入口被后门绕过**（安全路 P0-C/P0-D、部署路 P0-E/P0-F、前端路 P0-G）：租户管理员可自建含平台级权限的角色自绑（进而跨租户建删租户、改 `provider.base_url` 外泄厂家 API Key、覆盖 `dsh.patch_template`）；`repo.credential_id` 跨租户可用（他人 git 凭据被发往攻击者服务器）；全新 Docker 部署 100% 起不来、裸机文档配方等于公开 JWT 密钥 + 公开口令；前端任务级写操作无 in-flight 守卫。

建议本周只做四件事：修执行路的「假成功 + 告警抑制」链与工作区独占；给权限码划可授予层级并校验 `credential_id` 同租户；修部署引导（compose 注入 + 文档改账号密码主线）；给任务级写操作补前端防重。
