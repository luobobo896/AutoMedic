# AutoMedic 接口文档

> Base URL：`http://<host>:8080`
> API 前缀：`/api/v1`
> 所有请求/响应均为 `application/json; charset=utf-8`，时间字段为 RFC3339。
> 管理端为 **Vue3 + Element Plus**（不是 Element UI）。

---

## 1. 通用约定

### 1.1 响应包装

**成功**

```json
{ "code": 0, "message": "ok", "data": { } }
```

**分页**

```json
{
  "code": 0, "message": "ok",
  "data": {
    "list": [],
    "page": 1,
    "page_size": 20,
    "total": 128
  }
}
```

**失败**：HTTP 状态码即业务码，`data` 省略。

```json
{ "code": 401, "message": "无效的管理令牌" }
```

| code | 含义 |
| --- | --- |
| 0 | 成功 |
| 400 | 参数错误（message 为具体原因） |
| 401 | 鉴权失败 |
| 404 | 资源不存在 |
| 500 | 服务端错误 |

### 1.2 鉴权

| 接口组 | 鉴权方式 |
| --- | --- |
| `/api/v1/*`（管理面） | 请求头 `X-Admin-Token: <admin_token>`，或用 query `?admin_token=`。**未配置 `server.admin_token` 时放行** |
| `/api/v1/ingest/*`（投递面） | 请求头 `X-AM-Token: <token>`，或 `Authorization: Bearer <token>`，或 query `?token=` |
| `/ws/tasks/:id` | 无鉴权（内网使用；公网请通过 Nginx 加鉴权） |

CORS 已全开，允许的自定义头：`X-Admin-Token`、`X-AM-Token`。

### 1.3 分页

`page`（默认 1）、`page_size`（默认 20，上限 500）。

## 3. 项目

字段见 `projects` 表：`id / name / key(唯一) / description / fix_mode(auto|semi) / default_model_id / default_review_model_id / release_hook / enabled / context / created_at`。`default_review_model_id` 留空则审查与修复用同一套模型。

`release_hook` 即产品里的「发布」：push 成功后在隔离工作区目录执行的命令。项目级非空时覆盖系统设置 `git.release_hook`；都为空则跳过。不是独立 CI/CD 流水线。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/projects` | 列表，附 `repo_count`；支持 `?keyword=` |
| POST | `/api/v1/projects` | 新建 |
| GET | `/api/v1/projects/:id` | 详情 |
| PUT | `/api/v1/projects/:id` | 更新（只认业务字段；关联对象/时间戳会被忽略） |
| DELETE | `/api/v1/projects/:id` | 删除（有仓库时拒绝） |

**POST 示例**

```json
{
  "name": "电商中台",
  "key": "shop",
  "description": "订单/库存/支付服务",
  "fix_mode": "semi",
  "context": "Go 1.22 + Gin + GORM，MySQL 主从，代码在 internal/ 下",
  "enabled": true
}
```

## 4. 仓库

字段含 `model_id`（修复）与 `review_model_id`（审查，留空则与修复同一套）。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/repos` | 列表，支持 `?project_id=` |
| POST | `/api/v1/repos` | 新建 |
| GET | `/api/v1/repos/:id` | 详情 |
| PUT | `/api/v1/repos/:id` | 更新 |
| DELETE | `/api/v1/repos/:id` | 删除 |
| POST | `/api/v1/repos/:id/test` | 连通性测试（`git ls-remote`） |
| GET | `/api/v1/repos/:id/tree` | 浏览远端分支目录树（浅取 tip，管理鉴权） |
| GET | `/api/v1/repos/:id/file?path=` | 预览远端文本文件（限约 64KB，二进制只标记） |
| POST | `/api/v1/repos/:id/review` | 手动 OCR 审查（异步，立即返回 job） |
| GET | `/api/v1/reviews/:id` | 查询审查任务、findings、运行中 `progress`/`logs` |
| POST | `/api/v1/reviews/:id/fix` | 勾选 findings，为当前仓库创建半自动修复任务 |

**POST 示例**

```json
{
  "project_id": 1,
  "name": "shop-api",
  "url": "git@github.com:acme/shop-api.git",
  "branch": "main",
  "language": "go",
  "code_paths": "internal/,pkg/",
  "credential_id": 2,
  "model_id": 1,
  "auto_push": true,
  "enabled": true
}
```

**POST `/repos/:id/test` 响应**

```json
{ "code": 0, "data": { "ok": true, "cost_ms": 812 } }
```

失败返回 500，message 为 git 原始错误；同时写入一条 `credential_usages` 记录（action=`test`）。

**GET `/repos/:id/tree` 响应**

凭证路径与 `test` 相同（SSH / HTTP Token 注入）。浅 clone 远端 `branch` 最新提交，列出嵌套目录（跳过 `.git` / `node_modules` / `vendor` 等），最多约 2000 条。

```json
{
  "code": 0,
  "data": {
    "branch": "main",
    "truncated": false,
    "nodes": [
      { "name": "internal", "path": "internal", "type": "dir", "children": [
        { "name": "service.go", "path": "internal/service.go", "type": "file", "size": 128 }
      ]},
      { "name": "README.md", "path": "README.md", "type": "file", "size": 512 }
    ]
  }
}
```

**GET `/repos/:id/file?path=internal/service.go` 响应**

```json
{ "code": 0, "data": { "path": "internal/service.go", "content": "package internal\n...", "binary": false, "truncated": false, "size": 128 } }
```

`path` 必须是仓库内相对路径，拒绝 `..`。失败同样写入 `credential_usages`（action=`tree` / `file`）。

**POST `/repos/:id/review` 请求**

```json
{ "mode": "review", "from": "main" }
```

或 `{ "mode": "scan", "path": "internal/" }`。整仓扫描需 `{ "mode":"scan", "scan_all": true }`（Web 默认不开放）。立即返回 `status=pending`，后台取仓库 + 用平台厂家密钥调用官方 `ocr`。模型解析：仓库 `review_model_id` → 项目 `default_review_model_id` → 仓库/项目修复模型 → 全局默认。OCR 未安装、厂家无 API Key 或自定义厂家无 Base URL 时 `status=failed`，`error_msg` 为原因。

**GET `/reviews/:id` 响应（成功后）**

```json
{
  "code": 0,
  "data": {
    "id": 1,
    "status": "success",
    "mode": "review",
    "from_ref": "main",
    "to_ref": "feature",
    "finding_n": 1,
    "progress": "审查完成，1 条意见",
    "logs": ["仓库已就绪，解析审查模型", "正在审查 service/ShopService.java（deepseek-v4-pro）"],
    "findings": [
      { "key": "a1b2", "path": "internal/svc.go", "line": 12, "severity": "high", "rule": "NPE", "title": "空指针", "body": "u 可能为 nil" }
    ]
  }
}
```

**POST `/reviews/:id/fix`**

```json
{ "keys": ["a1b2"] }
```

跳过规则/频次/冷却，为当前仓库创建 `mode=semi`、`source=ocr` 的修复任务并入队。单次最多 20 条。

## 5. 凭证中心

类型：`ssh_key`（私钥）、`http_auth`（账号密码）、`http_token`（AccessToken）。
`secret` / `passphrase` 以 AES-256-GCM 加密存储，**列表接口只返回 `secret_masked`**。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/credentials` | 列表（含 `secret_masked` / `used_by` / `use_count` / `last_used_at`） |
| POST | `/api/v1/credentials` | 新建 |
| GET | `/api/v1/credentials/:id` | 详情 |
| PUT | `/api/v1/credentials/:id` | 更新（不传 `secret` 则不改密钥） |
| DELETE | `/api/v1/credentials/:id` | 删除（被仓库引用时拒绝） |
| GET | `/api/v1/credential-usages` | 使用记录，支持 `?credential_id=` |

**POST 示例**

```json
{
  "name": "GitHub 机器人私钥",
  "type": "ssh_key",
  "secret": "-----BEGIN OPENSSH PRIVATE KEY-----\n...",
  "passphrase": "",
  "description": "只读+推送修复分支",
  "enabled": true
}
```

### 6.1 厂家

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/providers` | 返回 `{providers: [...], models: [...]}`，厂家含 `api_key_masked` |

**POST 示例**

```json
{
  "name": "DeepSeek 官方",
```

`kind` 决定 API Key 注入 dsh 的环境变量名，见《dsh集成说明》第 4 节。

### 6.2 模型（逐模型配置输入/输出上下文）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/models` | 列表，支持 `?provider_id=` |
| POST | `/api/v1/models` | 新建 |
| GET | `/api/v1/models/:id` | 详情 |
| PUT | `/api/v1/models/:id` | 部分更新 |
| DELETE | `/api/v1/models/:id` | 删除（有任务引用时建议禁用） |

**POST 示例**

```json
{
  "provider_id": 1,
  "name": "DeepSeek V4 Flash",
  "slug": "deepseek-v4-flash",
  "input_context": 1048576,
  "output_context": 131072,
  "max_turns": 128,
  "temperature": "0.2",
  "extra_params": { "topP": 0.95 },

```

> `extra_params` 会被平铺进 dsh 的 `--patch` YAML；`is_default=true` 会自动把其他模型的默认标记清除。

## 7. 规则

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/rules` | 列表，支持 `?project_id=`，按 `priority DESC, id ASC` |
| POST | `/api/v1/rules` | 新建 |
| PUT | `/api/v1/rules/:id` | 部分更新 |
| DELETE | `/api/v1/rules/:id` | 删除 |

**POST 示例**

```json
{
  "project_id": 1,
  "name": "Go 服务 5xx / panic 自动修复",
  "enabled": true,
  "priority": 100,
  "levels": "fatal,error",
  "sources": "sentry,loki",
  "keywords": "panic,nil pointer,goroutine",
  "all_keywords": "",
  "exclude_keywords": "第三方限流,上游超时,权限不足,参数校验,余额不足",
  "exclude_sources": "",
  "pattern": "panic:\\s+runtime error",
  "min_count": 3,
  "window_sec": 300,
  "cooldown_sec": 3600,
  "action": "fix",
  "repo_ids": "1,2",
  "model_id": 1,
  "fix_mode": "semi",
  "max_retries": 3,
  "prompt_template": "必须补充单元测试，禁止修改 migrations 目录"
}
```

匹配逻辑（见 `service.MatchRule`）：

1. 按 `priority` 降序取第一条命中规则；
2. 依次校验：启用状态 → 级别白名单 → 来源白名单 → 排除来源 → **排除关键字** → 全部关键字 → 任一关键字 → 正则；
3. 命中后：频次阈值（`min_count` / `window_sec`）→ 冷却（`cooldown_sec`，同一指纹）→ 选仓库；
4. `action=ignore` 直接忽略；`action=fix` 生成任务。

## 8. 事件

### 8.1 投递（令牌鉴权）

**`POST /api/v1/ingest/events`**

请求头：`X-AM-Token: am_xxxx`

```json
{
  "source": "sentry",
  "level": "error",
  "title": "NullPointerException in OrderService",
  "message": "order.GetUser() 返回 nil 后访问 .ID",
  "stack": "panic: runtime error: invalid memory address\n\torder.(*Service).Get(...)",
  "fingerprint": "",
  "repo_hint": "shop-api",
  "occurred_at": "2026-09-03T17:00:00+08:00",
  "payload": { "env": "prod", "version": "v1.8.2" }
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` / `message` | 二选一 | 都为空则 400 |
| `level` | 否 | 默认 `error`；`fatal/error/warn/info` |
| `source` | 否 | 默认 `custom` |
| `fingerprint` | 否 | 留空则按 `source+title+stack 前3行` 自动生成 |
| `repo_hint` | 否 | 仓库名或 URL 片段，用于缩小到目标仓库 |
| `occurred_at` | 否 | 默认服务端当前时间 |

**响应**

```json
{
  "code": 0,
  "data": {
    "event": { "id": 42, "status": "matched", "dispose_msg": "规则命中：Go 服务 5xx；生成 1 个修复任务", "rule_id": 3 },
    "task_ids": [57],
    "action": "fix",
    "reason": "规则命中：Go 服务 5xx；生成 1 个修复任务"
  }
}
```

`action` 取值：

| action | 含义 |
| --- | --- |
| `fix` | 已生成修复任务并入队 |
| `ignore` | 未命中规则 / 规则动作为忽略 |
| `dropped` | 未达频次阈值 / 冷却中 / 无可用仓库 |

**`POST /api/v1/ingest/events/batch`**

```json
{ "events": [ { ... }, { ... } ] }   // 1~100 条
```

返回数组，逐条给出 `action`；单条失败记为 `{"action":"error","reason":"..."}`，不影响其他条目。

**鉴权错误**

| message | 场景 |
| --- | --- |
| `缺少投递令牌（X-AM-Token）` | 未带令牌 |
| `令牌无效` | 哈希不匹配 |
| `令牌已禁用` / `令牌已过期` | 状态/有效期不符 |
| `来源 IP 不在允许范围` | `allow_cidr` 不放行 |

### 8.2 管理面

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/events` | 列表，支持 `project_id / status / level / source / keyword / days` |
| GET | `/api/v1/events/:id` | 详情 + 关联任务列表 |
| POST | `/api/v1/events/:id/replay` | 重放（生成新指纹，绕过冷却） |

`status`：`received` / `matched` / `ignored` / `dropped`。

## 9. 任务

### 9.1 列表与详情

**`GET /api/v1/tasks`** — 过滤参数：`project_id / repo_id / status / mode / keyword / from / to / page / page_size`

```json
{
  "code": 0,
  "data": {
    "list": [{
      "id": 57, "status": "confirming", "mode": "semi", "stage": "dsh",
      "branch": "automedic/fix-57", "base_commit": "a1b2c3d",
      "project": { "id": 1, "name": "电商中台" },
      "repo": { "id": 1, "name": "shop-api" },
      "event": { "id": 42, "title": "..." },
      "rule": { "id": 3, "name": "..." },
      "model": { "id": 1, "name": "DeepSeek V4 Flash" },
      "summary": "补充 nil 检查", "diff_stat": "2 files changed, 18 insertions(+)",
      "dsh_model": "deepseek-v4-flash", "dsh_provider": "deepseek-official",
      "input_context": 1048576, "output_context": 131072,
      "duration_ms": 184230, "started_at": "...", "finished_at": "..."
    }],
    "page": 1, "page_size": 20, "total": 210
  }
}
```

**状态机**

| status | 含义 |
| --- | --- |
| `pending` | 待处理（已入队） |
| `running` | 处理中（dsh 执行中） |
| `confirming` | 待人工确认（半自动模式） |
| `success` | 成功（已提交推送） |
| `failed` | 失败 |
| `ignored` | 已忽略（含 dsh 判定 `no_code_change`） |
| `cancelled` | 已取消 |
| `rejected` | 人工驳回 |

`stage`：`pending → prepare → dsh → verify → commit → push → release`。

**`GET /api/v1/tasks/:id`** — 详情，含 `patch`、`changed_files`、`diagnosis`、`error_msg`、`dsh_cmd`。

### 9.2 终端日志

**`GET /api/v1/tasks/:id/logs`** — 轮询兜底接口

| 参数 | 说明 |
| --- | --- |
| `after_seq` | 增量拉取，返回 `seq > N` 的行 |
| `limit` | 1~5000，默认 1000 |

```json
{ "code": 0, "data": [
  { "id": 1, "task_id": 57, "seq": 1, "stream": "sys",    "content": "[dsh] profile=headless model=deepseek-v4-flash ...", "created_at": "..." },
  { "id": 2, "task_id": 57, "seq": 2, "stream": "stdout", "content": "Reading repository structure ..." }
] }
```

**WebSocket `GET /ws/tasks/:id`** — 实时推送，帧格式：

```json
{ "type": "log",    "data": { "seq": 3, "stream": "stdout", "content": "..." } }
{ "type": "status", "data": { "status": "running", "stage": "dsh" } }
{ "type": "done",   "data": { "status": "success" } }
```

慢客户端会丢帧（不阻塞执行），建议前端以 `after_seq` 轮询补偿。

### 9.3 操作

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/tasks/:id/patch` | 补丁全文 `{patch, diff_stat}` |
| POST | `/api/v1/tasks/:id/retry` | 重试（复制为新任务，`retry+1`，受规则 `max_retries` 限制，默认 3） |
| POST | `/api/v1/tasks/:id/cancel` | 取消（终止 dsh 进程） |
| POST | `/api/v1/tasks/:id/ignore` | 标记忽略 |
| POST | `/api/v1/tasks/:id/confirm` | 人工确认（半自动）：重建工作区 → apply 补丁 → commit → push → 钩子 |
| POST | `/api/v1/tasks/:id/reject` | 人工驳回，回退分支 |

**confirm / reject 请求体**

```json
{ "operator": "zhangsan", "note": "改动合理，同意合并" }
```

`confirm` 为异步执行（立即返回 `{confirming: id}`），进度通过终端日志观察。

## 11. 运行时设置

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/settings` | 读取 dsh / git / ocr 运行参数 |
| GET | `/api/v1/dicts` | 表单选项字典，`?group=` 过滤，`?all=1` 含停用项。`groups` 含 `parent_group`/`child_group`；项含 `parent_id`（厂家类型 → 模型标识） |
| POST | `/api/v1/dicts` | 新增选项；`model_slug` 可带 `parent_id` 或 `extra.kind` 自动挂到厂家 |
| PUT | `/api/v1/dicts/:id` | 更新 label/sort/enabled/extra/parent_id |
| DELETE | `/api/v1/dicts/:id` | 删除选项；有子项时拒绝 |
| PUT | `/api/v1/settings` | 热更新（立即生效，进程重启后回落到配置文件） |

## 12. WebSocket

**`GET /ws/tasks/:id`**

- 无鉴权（内网使用）
- 连接后即推送历史全量日志，随后实时增量
- 客户端只需读，无需发送任何帧
- 服务端对慢客户端丢帧而非阻塞，断线后前端用 `GET /api/v1/tasks/:id/logs?after_seq=N` 补齐

## 13. 端到端示例

```bash
TOKEN="am_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
ADMIN="your-admin-token"

# 1. 建项目
PID=$(curl -s -X POST http://127.0.0.1:8080/api/v1/projects \
  -H "X-Admin-Token: $ADMIN" -H "Content-Type: application/json" \
  -d '{"name":"Demo","key":"demo","fix_mode":"semi"}' | jq -r .data.id)

# 2. 建仓库
curl -s -X POST http://127.0.0.1:8080/api/v1/repos \
  -H "X-Admin-Token: $ADMIN" -H "Content-Type: application/json" \
  -d "{\"project_id\":$PID,\"name\":\"demo-api\",\"url\":\"https://github.com/acme/demo-api.git\",\"branch\":\"main\",\"language\":\"go\"}"

# 3. 建规则
curl -s -X POST http://127.0.0.1:8080/api/v1/rules \
  -H "X-Admin-Token: $ADMIN" -H "Content-Type: application/json" \
  -d "{\"project_id\":$PID,\"name\":\"默认\",\"levels\":\"fatal,error\",\"action\":\"fix\",\"min_count\":1,\"cooldown_sec\":0}"

# 4. 生成投递令牌
curl -s -X POST http://127.0.0.1:8080/api/v1/tokens \
  -H "X-Admin-Token: $ADMIN" -H "Content-Type: application/json" \
  -d "{\"project_id\":$PID,\"name\":\"demo\"}" | jq -r .data.plain_token

# 5. 投递事件
curl -s -X POST http://127.0.0.1:8080/api/v1/ingest/events \
  -H "X-AM-Token: $TOKEN" -H "Content-Type: application/json" \
  -d '{"source":"custom","level":"error","title":"panic: nil pointer","message":"o.GetUser().ID","stack":"main.main()"}'

# 6. 查看任务
curl -s "http://127.0.0.1:8080/api/v1/tasks" -H "X-Admin-Token: $ADMIN" | jq .data.list
```

完整脚本：`server/scripts/smoke.sh`。
