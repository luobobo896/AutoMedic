# 告警采集接入（Sentry / Loki / Sidecar）

> AutoMedic **不内置** Sentry、Loki、K8s 采集插件。所有告警源统一走 HTTP 投递：
>
> `POST /api/v1/ingest/events`（单条）或 `POST /api/v1/ingest/events/batch`（1~100 条）
>
> 鉴权：请求头 `X-AM-Token`（也支持 `Authorization: Bearer` 或 `?token=`）。
> 令牌在 Web「项目详情 → 投递令牌」或「项目令牌」页创建，明文只显示一次。

平台只认下面的 JSON 字段，采集器负责把源系统格式映射过来。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` / `message` | 二选一 | 都为空则 400 |
| `source` | 否 | 默认 `custom`；建议填 `sentry` / `loki` / `k8s` |
| `level` | 否 | 默认 `error`；`fatal` / `error` / `warn` / `info` |
| `stack` | 否 | 堆栈或日志上下文 |
| `fingerprint` | 否 | 去重键；留空由系统按 `source+title+stack 前 3 行` 生成。同一指纹：任务进行中会去重，历史已成功修复会过滤，不再开新修复任务 |
| `repo_hint` | 否 | 仓库名或 URL 片段，缩小定位范围 |
| `occurred_at` | 否 | RFC3339；默认服务端当前时间 |
| `payload` | 否 | 任意原始负载（对象） |

成功响应：`{ "code":0, "data": { "action":"fix|ignore|dropped", "task_ids":[...], "reason":"..." } }`。

## 1. Sentry Webhook

在 Sentry 项目 **Settings → Integrations → Webhooks**（或 Alert Rule 的 Webhook action）填：

- URL：`https://<automedic-host>/api/v1/ingest/events`
- Header：`X-AM-Token: <令牌>`、`Content-Type: application/json`

Sentry 发出的是 Issue / Event JSON，**不能原样投递**。用中间层（下面 sidecar，或 Sentry Internal Integration 的转发脚本）映射为平台字段。Issue Alert 常见字段对照：

| Sentry | AutoMedic |
| --- | --- |
| `data.event.title` / `issue.title` | `title` |
| `data.event.culprit` 或 message | `message` |
| `data.event.exception.values[0].stacktrace` 文本化 | `stack` |
| `data.event.level`（fatal/error/warning） | `level`（warning → warn） |
| `data.event.event_id` 或 `issue.id` | `fingerprint` |
| `project` / 服务名 | `repo_hint` |
| `data.event.timestamp` | `occurred_at` |
| 整份 webhook body | `payload` |

手工验证（把 Sentry 字段已经映射好之后）：

```bash
curl -s -X POST https://automedic.example.com/api/v1/ingest/events \
  -H "Content-Type: application/json" \
  -H "X-AM-Token: am_xxxxxxxx" \
  -d '{
    "source": "sentry",
    "level": "fatal",
    "title": "TypeError: Cannot read properties of undefined (reading id)",
    "message": "order service checkout",
    "stack": "TypeError: ...\n    at Service.checkout (internal/order/service.go:128)",
    "fingerprint": "sentry-issue-12345",
    "repo_hint": "shop-api",
    "payload": { "project": "shop", "environment": "production" }
  }'
```

## 2. Loki / Promtail / Grafana Alerting

Loki 本身不推送「一条告警一条 HTTP」。常见两条路：

### 2.1 Grafana Alerting Webhook（推荐）

在 Grafana 联系点（Contact Point）选 Webhook：

- URL：`https://<automedic-host>/api/v1/ingest/events`
- HTTP Header：`X-AM-Token: <令牌>`

Grafana 默认 body 也不是平台格式。用 Contact Point 的 **message** 模板直接输出 JSON，或走 sidecar。模板示例（Grafana 9+）：

```text
{{ define "automedic.default.message" }}
{
  "source": "loki",
  "level": "error",
  "title": {{ .CommonLabels.alertname | toJson }},
  "message": {{ .CommonAnnotations.summary | toJson }},
  "stack": {{ .CommonAnnotations.description | toJson }},
  "fingerprint": {{ .GroupKey | toJson }},
  "repo_hint": {{ .CommonLabels.service | toJson }},
  "payload": { "labels": {{ .CommonLabels | toJson }} }
}
{{ end }}
```

若 Grafana 无法自定义 JSON，把 Webhook URL 指到 sidecar：`http://automedic-sidecar:8091/loki`。

### 2.2 Promtail pipeline + webhook

Promtail 没有一等 webhook 输出。需要的话用 pipeline 把匹配行写到本地脚本 / Vector / Fluent Bit，再 POST 到 ingest。字段建议：

```json
{
  "source": "loki",
  "level": "error",
  "title": "panic: runtime error: invalid memory address",
  "message": "shop-api pod shop-api-7d9c",
  "stack": "<连续若干行日志>",
  "fingerprint": "<service>-<第一行 panic>",
  "repo_hint": "shop-api"
}
```

## 3. Sidecar（可选）

仓库提供一个无依赖转发器：[`deploy/sidecar/ingest-sidecar.py`](../deploy/sidecar/ingest-sidecar.py)。

职责：接收 Sentry / Grafana Loki webhook 的原始 JSON，映射成 ingest 字段后转发。**不是**平台内置插件，可不部署。

```bash
export AUTOMEDIC_INGEST_URL=http://127.0.0.1:8080/api/v1/ingest/events
export AUTOMEDIC_INGEST_TOKEN=am_xxxxxxxx
python3 deploy/sidecar/ingest-sidecar.py   # 默认 :8091
```

| 路径 | 用途 |
| --- | --- |
| `POST /sentry` | Sentry Issue / Event webhook |
| `POST /loki` | Grafana Alerting webhook（`alerts` 数组） |
| `POST /` 或 `POST /raw` | 已是平台格式则原样转发 |

K8s 示例：把 sidecar 与采集器同 Pod，或单独 Deployment，Sentry/Grafana 只打 sidecar。

## 4. 排障

| 现象 | 处理 |
| --- | --- |
| 401 `缺少投递令牌` / `令牌无效` | 检查 `X-AM-Token` 是否为创建时的明文，不要用 prefix |
| `令牌已禁用` / `已过期` | Web 令牌页启用或重建 |
| `来源 IP 不在允许范围` | 放宽 `allow_cidr`，或让 sidecar 出口 IP 在白名单内 |
| `action=ignore` | 规则未命中或动作为忽略；查「事件」页 `dispose_msg` |
| `action=dropped` | 频次阈值 / 冷却 / 无可用仓库 |
| 400 title/message 皆空 | 映射失败，先用 curl 对照 §1 样例 |
