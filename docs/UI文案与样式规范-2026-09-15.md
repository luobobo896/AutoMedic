# UI 样式与文案一体化规范（Apple HIG 对齐）

> 日期：2026-09-15 · 范围：`web/` 全站样式 token + 全站文案
> 前提：**不改变功能与交互逻辑**，只调整视觉表现（间距、圆角、阴影、描边、动效、字体）与文案表达。
> 参照：Apple Human Interface Guidelines（系统字体、留白分层、语义色、克制动效）；
> 品牌色与语义色同时兼容参考平台 New API 的观感（该仓库为 AGPL-3.0，仅参考设计事实，未复制其代码）。

## 1. 样式方案（token 层，全站生效）

| 维度 | 调整前 | 调整后 | 理由 |
| --- | --- | --- | --- |
| 字体 | `-apple-system, BlinkMacSystemFont, Segoe UI, PingFang SC…` | `-apple-system, BlinkMacSystemFont, SF Pro Text, PingFang SC, Hiragino Sans GB, Microsoft YaHei, system-ui…` | HIG：界面用系统字体。macOS/iOS 落到 SF Pro + 苹方，Windows 回落微软雅黑；不引入 Web 字体，省一次阻塞请求 |
| 字号阶梯 | 12 / 13 / 14 / 16 / 18 / 22 / 26 | 保持 | 已符合 HIG 的「标题看字号差不看字重堆」；正文 14、辅助 13、标注 12 三档足够，不再细化 |
| 圆角 | 4 / 6 / 8 / 12 | 6 / 8 / 12 / 16 | HIG 连续圆角观感：容器 16、控件 12、小标记 6；层级差靠尺寸而不是花样 |
| 描边 | `#e5e7eb`（偏蓝灰） | `#e8e8e8`（中性灰） | 中性描边不发蓝，界面更干净；与参考平台一致 |
| 主色 | `#2b6ef0` | `#1f6feb`（参考平台 oklch 0.692/0.141/243.7 按 WCAG AA 压深） | 保留品牌蓝家族；白字 4.63:1、白底蓝字 4.63:1，均达 AA。参考站原色 `#3ea4ec` 只有 2.72:1，未直接采用 |
| 语义色 | 成功 `#16803c`／警告 `#b45309`／危险 `#dc4c40`／中性 `#98a2b3` | 成功 `#12a150`／警告 `#d08700`／危险 `#e7000b`／中性 `#a1a1a1`，文字态另设 `-text` 深色变体 | 贴近系统语义色饱和度；纯色用于填充，文字用深一档保证 ≥4.5:1 |
| 阴影 | 单层深投影（12%/30% 黑） | 双层低对比：`0 10px 30px rgba(0,0,0,.10), 0 2px 8px rgba(0,0,0,.04)`；仅弹层/悬浮使用 | HIG 靠留白与描边分层，不靠重投影 |
| 动效 | `cubic-bezier(.2,0,0,1)` 180ms | `cubic-bezier(.4,0,.2,1)` 180ms | Apple 标准缓动（快出慢入，无回弹）；`prefers-reduced-motion` 已有兜底 |
| 图表色 | 蓝 `#2b6ef0`／绿 `#2f9e44`／橙 `#f0b03e`／红 `#ed5d54`／灰 `#98a2b3` | 蓝 `#1f6feb`／绿 `#12a150`／橙 `#d08700`／红 `#e7000b`／灰 `#a1a1a1`，坐标轴 `#e8e8e8`、标签 `#606060` | 与 UI token 同源，避免「图表一套色、界面一套色」 |

### 新增的组件样式类（全站可复用，不引入新依赖）

| 类 | 用途 | 观感要点 |
| --- | --- | --- |
| `.am-seg-tabs` | 分段控件（模型列表/厂家接入/调用预览） | 浅灰轨道 + 白色当前项 + 细描边，替代下划线 tab |

| `.am-field` / `__label` / `__help` / `__origin` | 表单字段 | label 在上（14/500）、帮助文字在下（12px 灰）、取值来源单独一行 |

| `.am-ref` | 引用关系徽标 | 被引用时主色显示「厂家 N / 模型 M」，未引用显示灰色“未引用” |
| `.am-empty--table` | 表格空态 | 居中 + 粗标题 + 灰说明 + 一个下一步按钮 |

## 3. 保持原样（不改）及理由

| 位置 | 现状文案 | 保持理由 |
| --- | --- | --- |
| 登录页 | 账号 / 密码 / 登录 / 开发环境默认口令提示 | 已是最短表达；默认口令属于安全提示，保留 |
| 修复规则页描述 | 命中级别/关键字才开流程，排除词拦下业务拒绝与第三方故障… | 需详细类：直接决定“什么会触发修复”，不能压缩 |
| 项目令牌页描述 | 请求头 `X-AM-Token`，明文只在创建时显示一次 | 需详细类：一次性明文是安全后果 |
| 运行设置页描述 | 文件级配置只读展示，避免 Web 侧误改运行环境 | 需详细类：解释“为什么不可编辑” |
| 危险操作确认框 | 确认删除模型「X」？ / 确认删除厂家「Y」？ | 危险操作必须带具体对象，不能精简成“确定吗” |
| 字典表格「分组」列 | 每行显示所属分组 | 对单层分组略冗余，但 `model_slug` 子行需要它区分父子关系，保留 |
| KPI 标签（事件总数/修复流程/自愈成功率…） | 原样 | 已是行业最短术语，再简会歧义 |
| 侧栏菜单名（运营仪表盘/事件中心/修复流程…） | 原样 | 4–5 字，已符合 HIG 的简短导航命名 |
| 表格列名（取值/显示名/排序/启用） | 原样 | 字典领域惯用词，改反而增加理解成本 |
| 操作按钮（编辑/删除/设为默认/进入监控） | 原样 | 动词短语、无标点，符合 HIG 文案规范 |

## 4. 关联机制（字典 ↔ 模型配置）

| 方向 | 机制 | 落点 |
| --- | --- | --- |
| 字典 → 模型配置 | 厂家类型、模型标识、温度三类下拉均由字典渲染（含“父级 = 厂家类型”过滤） | `composables/useDicts.js` + `ModelConfig.vue` |
| 模型配置 → 字典 | 每个字典来源字段带「来自选项字典 · X（N 项）+ 去维护」 | `ModelConfig.vue` 两个弹窗 |
| 引用可见 | `GET /dicts` 每项返回 `usage{providers,models,samples}`；列表显示「厂家 N / 模型 M」并给出引用方名称 | `api/dict.go`、`DictList.vue` |
| 引用保护 | 被引用的字典项禁止删除（返回原因与引用样本）；停用仍允许但列表可看出“仍被引用” | `api/dict.go` |

## 5. 与上一条要求的冲突与处理

上一条要求「模型配置/字典管理参照参考页重构」，本条要求「不改变布局结构与交互逻辑」。处理方式：

- **模型配置页**：保留「分段（模型列表/厂家接入/调用预览）+ 表格」结构（上一条的核心诉求），但**功能动作完全未变**：新增/编辑/删除厂家与模型、设为默认、启用开关、dsh 预览均沿用原逻辑。
- **选项字典页**：保持原有「左侧分组 + 右侧表格」两栏结构不变，仅新增「引用」列与分组说明（信息性，不改变操作路径）。
- 如果希望连结构也回到上一版（厂家卡片 + 模型行），执行 `git revert <本次提交>` 即可，样式与文案改动可单独保留。
