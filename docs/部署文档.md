# AutoMedic 部署文档

> 事件驱动的 DeepSeek Harness（dsh）全自动 / 半自动 Bug 修复平台。
> 技术栈：Go 1.23（Gin + GORM）后端 · **Vue3 + Element Plus** 前端（不是 Element UI）· PostgreSQL · dsh headless。

---

## 1. 架构与端口

```
 ┌────────────┐   X-AM-Token    ┌──────────────────────────────────────┐
 │ Sentry/    │ ──────────────► │  AutoMedic Server (:8080)            │
 │ Loki/K8s/  │  POST /api/v1/  │  ├─ 规则引擎（过滤非代码问题）        │
 │ 自定义采集 │   ingest/events │  ├─ 任务调度（worker pool）           │
 └────────────┘                 │  ├─ git 隔离工作区（clone/fetch/push）│
                                │  ├─ dsh headless 调用 + 日志采集      │
 ┌────────────┐  X-Admin-Token  │  └─ 统计 / Web 静态资源托管           │
 │  浏览器    │ ◄─────────────► └───────────────┬──────────────────────┘
 │  :8080     │   WS /ws/tasks/:id              │ fork/exec
 └────────────┘                                 ▼
                                 ┌──────────────────────────────────────┐
                                 │ dsh --profile headless               │
                                 │ （cwd = 隔离工作区，仅工作区可写）    │
                                 └──────────────────────────────────────┘
```

对外只有一个端口 `8080`：REST API、WebSocket、前端静态资源全部由 Go 进程提供（可选前置 Nginx）。

## 2. 环境依赖

| 组件 | 版本要求 | 说明 |
| --- | --- | --- |
| Go | ≥ 1.23（仅构建需要） | 运行时为静态二进制，无 Go 依赖 |
| Node.js | ≥ 20 | **运行时必需**，dsh 是 node CLI |
| dsh | 官方最新版 | DeepSeek Harness，须可执行且能 `dsh --version` |

安装 dsh（官方 npm 包，scope 为 `@deepseek-ai`）：

```bash
npm install -g @deepseek-ai/dsh
dsh --version                    # 当前 latest: 0.1.2-rc.1
which dsh                        # 记下绝对路径，填到 dsh.bin
```

> ⚠️ 不要安装 `@deepseek/dsh` 或 `dsh`，这两个都不是官方包。
> 若 dsh 由 fnm / nvm 管理，务必把对应 node 的 bin 目录写进 `dsh.env` 的 `PATH`，
> 否则服务 fork 出的子进程找不到 dsh（报错 `dsh: command not found`）。
| git | ≥ 2.30 | clone / fetch / commit / push |
| openssh-client | 任意 | SSH 协议仓库克隆需要 |
| PostgreSQL | ≥ 16 | 唯一数据库；表结构由启动时 AutoMigrate 幂等补齐 |

## 3. 方式一：Docker Compose（推荐）

### 3.1 准备

```bash
git clone <your-repo> automedic && cd automedic
cp .env.example .env

# 生成管理令牌（务必替换默认值）；加密主密钥建议留空，交由容器自动生成
openssl rand -hex 24                 # → AUTOMEDIC_ADMIN_TOKEN
# openssl rand -base64 32            # 仅当你想显式指定 AUTOMEDIC_SECRET_KEY 时才用
# 把结果填入 .env
```

> ⚠️ `AUTOMEDIC_SECURITY_SECRET_KEY` 用于 AES-256-GCM 加密 git 凭证与厂家 API Key。
> **一旦更换，已存凭证将无法解密，需要重新录入。请勿在首次上线后随意变更。**
>
> Docker 部署时若未显式提供该变量，`deploy/docker-entrypoint.sh` 会在数据卷
> `/app/data/.secret_key` 生成一个随机密钥并长期复用，避免容器重建后凭证失效。
> 该文件权限为 `0600`，请随数据卷一起备份。

### 3.2 启动

```bash
docker compose up -d
docker compose logs -f automedic
curl http://127.0.0.1:8080/healthz      # → {"status":"ok"}
```

浏览器打开 <http://localhost:8080>，首次进入在右上角「设置」填入 `AUTOMEDIC_ADMIN_TOKEN` 的值。

### 3.3 数据持久化

| 卷 | 内容 |
| --- | --- |
| `automedic-data` | git 工作区 `/app/data/workspaces`、日志 `/app/data/logs`、加密主密钥 `/app/data/.secret_key` |
| `automedic-pg` | PostgreSQL 数据目录 |

### 3.4 关于镜像内的 dsh

Dockerfile stage 3 通过官方 npm 包安装 dsh：

```dockerfile
ARG DSH_VERSION=latest
RUN npm install -g "@deepseek-ai/dsh@${DSH_VERSION}" --no-audit --no-fund
```

> **包名必须是 `@deepseek-ai/dsh`（scope 带 `-ai`）**。`@deepseek/dsh` 与 `dsh` 均不是官方包，
> 误用会装到无关甚至恶意的包。当前 latest 版本：`0.1.2-rc.1`。

可选：用 build-arg 锁定版本

```bash
docker build --build-arg DSH_VERSION=0.1.2-rc.1 -t automedic:latest .
```

若你的环境无法访问 npm，或发行渠道有变，二选一：

1. **挂载宿主机 dsh**（推荐）：宿主机 `npm i -g @deepseek-ai/dsh` 后，在 `docker-compose.yml` 加
   ```yaml
   volumes:
     - /usr/local/lib/node_modules/@deepseek-ai:/usr/local/lib/node_modules/@deepseek-ai:ro
   ```
2. **自维护基础镜像**：改 `Dockerfile` 的 stage 3，用你自己的已装 dsh 的镜像作为 base，并把 `serverbuild` 产出的二进制与 `web/dist` COPY 进去。

## 4. 方式二：裸机部署（systemd）

### 4.1 构建

```bash
./scripts/build.sh                 # 产出 server/bin/automedic-server 与 web/dist
```

### 4.2 安装

```bash
sudo useradd -r -m -d /opt/automedic -s /bin/bash automedic
sudo mkdir -p /opt/automedic/{configs,data,migrations,web}
sudo cp server/bin/automedic-server /opt/automedic/
sudo cp -r web/dist                /opt/automedic/web/
sudo cp server/migrations/*.sql    /opt/automedic/migrations/
sudo cp server/configs/config.yaml /opt/automedic/configs/
sudo chown -R automedic:automedic /opt/automedic
```

`/opt/automedic/.env`：

```bash
AUTOMEDIC_SERVER_ADMIN_TOKEN=<随机串>
AUTOMEDIC_SECURITY_SECRET_KEY=<openssl rand -base64 32>
AUTOMEDIC_SERVER_WEB_DIR=/opt/automedic/web/dist
AUTOMEDIC_DB_DRIVER=postgres
AUTOMEDIC_DB_DSN=host=/var/run/postgresql user=automedic dbname=automedic sslmode=disable TimeZone=Asia/Shanghai
AUTOMEDIC_DSH_BIN=/usr/local/bin/dsh
AUTOMEDIC_GIT_WORKSPACE_ROOT=/opt/automedic/data/workspaces
```

### 4.3 启动服务

```bash
sudo cp deploy/automedic.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now automedic
sudo systemctl status automedic
journalctl -u automedic -f
```

## 5. PostgreSQL

唯一支持的数据库。建库脚本见 `docs/database/001_create_database.sql`。

```bash
sudo -u postgres createuser -l automedic
sudo -u postgres createdb -O automedic automedic
sudo -u postgres psql -d automedic -c "GRANT ALL ON SCHEMA public TO automedic; ALTER SCHEMA public OWNER TO automedic;"
```

配置 `db:` 段：

```yaml
db:
  driver: "postgres"
  dsn: "host=/var/run/postgresql user=automedic dbname=automedic sslmode=disable TimeZone=Asia/Shanghai"
```

或用环境变量 `AUTOMEDIC_DB_DRIVER=postgres` + `AUTOMEDIC_DB_DSN=...`。TCP 示例：

```text
host=127.0.0.1 user=automedic password=StrongPass dbname=automedic port=5432 sslmode=disable TimeZone=Asia/Shanghai
```

> 程序启动时执行 `AutoMigrate`（幂等，只补表/索引，不删数据）。SQLite / MySQL 已移除，不再接受这两种 driver。

## 6. 配置项说明

配置文件：`server/configs/config.yaml`（Docker 内为 `/app/configs/config.yaml`，源自 `config.docker.yaml`）。
所有字段可用 `AUTOMEDIC_` 前缀环境变量覆盖，**优先级：环境变量 > 配置文件 > 内置默认值**。

| 段 | 字段 | 默认 | 环境变量 | 说明 |
| --- | --- | --- | --- | --- |
| server | `addr` | `:8080` | `AUTOMEDIC_SERVER_ADDR` | 监听地址 |
| server | `mode` | `release` | `AUTOMEDIC_SERVER_MODE` | 生产务必 `release` |
| server | `web_dir` | — | `AUTOMEDIC_SERVER_WEB_DIR` | 前端产物目录，留空不托管静态资源 |
| server | `admin_token` | `change-me` | `AUTOMEDIC_SERVER_ADMIN_TOKEN` | 管理 API 令牌，前端 `X-Admin-Token` |
| server | `read/write_timeout` | 60 / 300 | — | 秒 |
| db | `driver` | `postgres` | `AUTOMEDIC_DB_DRIVER` | 仅 `postgres` |
| db | `dsn` | 见默认配置 | `AUTOMEDIC_DB_DSN` | PostgreSQL DSN，见第 5 节 |
| db | `max_open/max_idle` | 50 / 10 | — | 连接池 |
| db | `log_level` | `warn` | — | silent/error/warn/info |
| security | `secret_key` | 空 | `AUTOMEDIC_SECURITY_SECRET_KEY` | **必填**，≥32 字节，加密主密钥 |
| security | `secret_key_file` | 空 | `AUTOMEDIC_SECURITY_SECRET_KEY_FILE` | 从文件读（优先级低于 secret_key） |
| dsh | `bin` | `dsh` | `AUTOMEDIC_DSH_BIN` | 建议绝对路径 |
| dsh | `home` | 空 | `AUTOMEDIC_DSH_HOME` | dsh 配置目录 |
| dsh | `command_template` | 见下 | — | 调用模板，详见《dsh集成说明》 |
| dsh | `use_shell` | `true` | — | 模板含 `$(cat …)` 时须为 true |
| dsh | `timeout_sec` | `1800` | — | 单次修复超时 |
| dsh | `permission_mode` | `workspace-write` | `AUTOMEDIC_DSH_PERMISSION_MODE` | 安全边界，勿改为 full access |
| dsh | `patch_template` | 见下 | — | 模型/上下文注入模板 |
| dsh | `instruction_file` | `AUTOMEDIC.md` | — | 写入工作区的指令文件 |
| dsh | `env` | — | — | 追加给 dsh 进程的环境变量 |
| git | `workspace_root` | `data/workspaces` | `AUTOMEDIC_GIT_WORKSPACE_ROOT` | 隔离工作区根目录 |
| git | `depth` | `1` | — | clone 深度，0 = 全量 |
| git | `reuse_workspace` | `true` | — | 复用工作区增量 fetch |
| git | `branch_prefix` | `automedic/fix-` | — | 修复分支前缀 |
| git | `author_name/email` | AutoMedic | — | commit 作者 |
| git | `auto_push` | `true` | — | 全自动模式下是否推送 |
| git | `release_hook` | 空 | — | 「发布」= 推送成功后在仓库目录执行的命令；项目 `release_hook` 非空时覆盖。留空不执行 |
| git | `keep_days` | `7` | — | 工作区保留天数 |
| ocr | `bin` | `ocr` | `AUTOMEDIC_OCR_BIN` | Open Code Review CLI；仓库「审查」按钮调用。LLM 用大模型配置中心，与 dsh 同一套密钥 |
| ocr | `timeout_sec` | `600` | — | 单次审查超时 |
| ocr | `env` | 空 | — | 传给 ocr 进程的额外 KEY=VALUE（PATH 等；不要配第二套 API Key） |
| log | `level` / `dir` / `retain` / `format` | info / 空 / 14 / text | `AUTOMEDIC_LOG_LEVEL` | dir 留空仅输出 stdout |

关键默认值：

```yaml
command_template: '{{.Bin}} --profile headless {{.Patches}} "$(cat {{.TaskFile}})"'
patch_template: |
  - id: agent-default-model
    config:
      provider: {{.Provider}}
      model: {{.Model}}
      inputContextTokens: {{.InputContext}}
      outputContextTokens: {{.OutputContext}}
  {{.ExtraYAML}}
```

> Web「系统设置」页可热改 dsh / git / ocr 参数（立即生效，进程重启后回落到配置文件）。仓库审查流程见 [ocr审查.md](ocr审查.md)。

## 7. 上线后的初始化清单

1. 用 `AUTOMEDIC_ADMIN_TOKEN` 登录 Web。
2. **模型配置** → 选中厂家 → 填 API Key（AES 加密存储）；确认默认模型的输入/输出上下文。
3. **凭证中心** → 新建凭证（SSH 私钥 / 账号密码 / HTTP Token），可跨项目复用。
4. **项目管理** → 新建项目 → 填 `key`、业务背景（`context` 会写入 dsh 指令文件）、修复模式（auto/semi）。
5. **项目详情 → 仓库** → 添加仓库，绑定凭证，"测试连接"验证可达性；"目录树"可浏览远端分支整体结构（浅取 tip）。
6. **项目详情 → 规则** → 至少建一条兜底规则：
   - 命中：`level ∈ {error, fatal}`
   - 排除：`第三方限流, 上游超时, 权限不足, 参数校验失败, 余额不足`（业务拒绝/外部故障不触发改代码）
   - 频次：`min_count=3 / window_sec=300` 抑制偶发抖动
   - 冷却：`cooldown_sec=3600` 防同一问题反复修复
7. **项目详情 → 令牌** → 生成投递令牌。Sentry / Loki 不能原样 POST 其 webhook JSON，字段映射与可选 sidecar 见 [采集接入.md](采集接入.md)。最小 curl：

```bash
curl -X POST https://automedic.example.com/api/v1/ingest/events \
  -H "X-AM-Token: am_xxxxxxxx" -H "Content-Type: application/json" \
  -d '{
        "source":"sentry","level":"error",
        "title":"NullPointerException in OrderService",
        "message":"...","stack":"...","repo_hint":"shop-api"
      }'
```

## 8. Nginx 反向代理

```bash
sudo cp deploy/nginx.conf /etc/nginx/conf.d/automedic.conf
sudo nginx -t && sudo systemctl reload nginx
```

三个要点：

- `location /ws/` 必须带 `Upgrade` / `Connection` 头，否则任务终端黑屏；
- `proxy_read_timeout` 需 ≥ `dsh.timeout_sec`（示例给 3600s）；
- `client_max_body_size` ≥ 10m（堆栈较长）。

## 9. 运维与故障排查

### 9.1 健康检查

```bash
curl -fsS http://127.0.0.1:8080/healthz        # {"status":"ok"}
curl -H "X-Admin-Token: $TOKEN" http://127.0.0.1:8080/api/v1/overview
```

### 9.2 常见问题

| 现象 | 排查 |
| --- | --- |
| 任务卡在 `pending` | 检查 worker 是否被前一个 dsh 任务占满（`GET /api/v1/tasks?status=running`）；看服务日志是否报 `dsh` 找不到 |
| `dsh: command not found` | 容器内 node 与 dsh 的 bin 目录要在 `dsh.env` 的 `PATH` 里；`dsh.bin` 用绝对路径 |
| clone 报权限错误 | 凭证类型与仓库 URL 协议要匹配（`git@` → ssh_key，`https://` → http_auth/http_token）；看「凭证中心 → 使用记录」 |
| clone 报分支不存在 | 平台会自动回退到远端默认分支；仍失败则检查仓库 `branch` 配置 |
| 任务一直 `confirming` | 半自动模式需人工在 Web 点「确认」；或把项目 `fix_mode` 改 `auto` |
| 大量 `no_code_change` | 这是过滤机制生效（非代码问题/仓库无对应源码）；检查规则排除词是否过宽或过窄 |
| 前端白屏 | 确认 `server.web_dir` 指向 `web/dist` 且包含 `index.html`；`curl -I http://127.0.0.1:8080/` 应 200 |
| 终端无输出 | 检查 WS 是否被代理拦截；前端会自动降级轮询 `GET /api/v1/tasks/:id/logs` |

### 9.3 数据维护

| 对象 | 位置 | 清理策略 |
| --- | --- | --- |
| git 工作区 | `git.workspace_root` | 内置 janitor 按 `keep_days` 自动清理 |
| 任务日志 | `task_logs` 表 | 建议按月归档：保留近 90 天任务及其日志 |
| 数据库 | PostgreSQL | `pg_dump -Fc automedic` 定期备份 |

### 9.4 备份前必读

备份 PostgreSQL 或导出配置时，**务必同时保管 `AUTOMEDIC_SECURITY_SECRET_KEY`**——凭证与 API Key 都以它加密，密钥丢失等于数据不可用。

## 10. 安全基线

| 项 | 建议 |
| --- | --- |
| `admin_token` | 强随机；生产环境不要留 `change-me` |
| `secret_key` | `openssl rand -base64 32`；不与代码库同仓 |
| `dsh.permission_mode` | 保持 `workspace-write`，禁止 `danger-full-access` |
| 投递令牌 | 绑定来源 IP CIDR、设置过期时间 |
| 网络 | 平台只放行 8080 出方向到 git 服务器与大模型 API；不要暴露到公网（或用 Nginx + 鉴权 + HTTPS） |
| 日志脱敏 | 内置 `redactSecrets()` 对 `KEY`/`TOKEN` 类环境变量脱敏；仍建议限制日志访问权限 |

## 12. 香港 HK 测试机一键部署（源码）

本机执行（SSH alias：`hk` → `hk.hsddns.com`）：

```bash
./scripts/deploy-hk.sh
# 依赖已就绪、只想同步源码并重建时：
./scripts/deploy-hk.sh --skip-deps
```

脚本会：

1. 用 rsync 把当前工作区源码同步到 `/opt/automedic/src`（排除 `.env`、`node_modules`、`dist`、数据库）。
2. 在 HK 上检查并安装/升级依赖到候选最新版；已是最新则跳过：`git`、`nodejs`（NodeSource）、`nginx`、`openssh-client`、`curl`、`ca-certificates`、`openssl`、`postgresql`、`rsync`、官方 Go、`@deepseek-ai/dsh`、`@alibaba-group/open-code-review`。创建 PostgreSQL 库 `automedic`（角色 `automedic`，peer 认证）。
3. 在服务器上从源码构建后端二进制与前端（`base=/automedic/`）。
4. 以 `automedic` 系统用户 + systemd 运行，监听 `127.0.0.1:8087`。
5. **覆盖** `hk.hsddns.com` 站点里废弃的 `location /automedic/`，反代到 8087（含 WebSocket）。

访问：<https://hk.hsddns.com/automedic/>  
健康检查：<https://hk.hsddns.com/automedic/healthz>

首次部署会生成 `/opt/automedic/.env` 与 `/opt/automedic/data/.secret_key`，管理令牌只打印一次（日志中的 `FIRST_ADMIN_TOKEN`）。后续部署不覆盖已有密钥。

HK 上根路径 `/api/`、`/` 仍属于 WhatsApp AI，因此 AutoMedic 必须走 `/automedic/` 子路径，不能占用 `:8080`。
